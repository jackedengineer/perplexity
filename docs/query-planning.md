# Planning and evidence interpretation

The original accepted user message remains authoritative and unchanged. Planning is a private, tool-free structured call using an explicitly assigned MODEL_PLANNER and PLANNER_OPENROUTER_PROVIDER. No answer/safety-role configuration is silently reused. The planner has one attempt, a five-second deadline and a 1,024-output-token ceiling. Provider routing requires privacy controls and price ceilings ($0.075/$0.20 per million input/output tokens).

The validator rejects invented topical vocabulary, numbers, assumptions and constraints without a literal USER-message quote and matching server message ID. Assistant history may identify an entity but cannot supply a user budget or serve as current evidence. This conservative lexical check is not semantic equivalence or a safety proof. Every outbound query still needs independent safety approval.

A clarification is one short question, never an answer or a URL. It is still private until output safety approval and atomic persistence. An unavailable planner may fall back to the exact original only for a short, unambiguous standalone explanatory question; ambiguous references fail closed. Search fanout and publication filters are server bounded. Authenticated conversation history and the current clock/locale are server inputs, not browser-supplied history.

Initial verification: ten offline tests cover model-role isolation, bounded structured dispatch, receipt retention, invented scope, negation/budgets, assistant constraint laundering, ambiguous references, freshness invention, no-tool planning, and unavailable-provider fallback. Live relevance and independent human acceptance are separate checks.

## Execution and clarification

Plans are immutable, private `run_plans` rows tied by composite foreign keys to the owned run and accepted USER message. The planner's 2,000 microUSD stage fits the existing 50,000 microUSD reservation. Original-text hashes and selected context IDs preserve provenance without public prompt telemetry. Provider work stays outside transactions and continuation rechecks owner, attempt, revision and absolute deadline.

Context selection uses at most six whole recent approved messages and 6,000 characters, with canonical output hashes and terminal-state verification for assistant turns. Older messages outside that explicit window are not a semantic memory guarantee. Every new follow-up is reclassified with the selected context. Unavailable, stale or malformed context fails closed.

Clarification has a dedicated terminal state, approved history/status delivery and zero answer credits. Atomic completion checks that its text exactly matches the stored CLARIFY plan and that no retrieval or answer was dispatched. The next reply gets a new idempotency key, admission, reservation and plan in the same owned conversation. A composer remounts per intent, preserving recovery of uncertain requests and the committed revision for immediate replies.

## Reproducible evaluation

`evals/cases/planning.jsonl` contains 30 authored expectations: 12 standalone, six constrained, five ambiguous, five contextual follow-ups and two false premises. They are explicitly unreviewed by humans. The offline comparison uses identical synthetic frozen source registries for original versus interpreted questions: expected plans select the intended source first in 25/25 answer cases, versus 20/25 with the unresolved original query. This controlled lexical proxy demonstrates reference resolution; it is not measured answer accuracy or a real-web relevance benchmark. Five ambiguous cases require clarification, with zero unnecessary clarifications in the authored baseline.

The opt-in live command is `LIVE_PLANNING_EVAL=1 pnpm exec vitest run --config vitest.planning.config.ts`. It requires a clean committed candidate, verifies the existing non-resetting $1 key cap, limits the complete run to 180 requests and $0.25 including unknown-call reservations, and never calls Tavily or touches any database. It exercises input/query guards, all 30 plans, guarded clarification and 14 paired answers for follow-ups/false premises against the same frozen evidence. It records planner cost/latency, all-role cost, routing and source-selection denominators. A restricted local review packet preserves every result, including unavailable/withheld outputs. Independent human ratings and factual-support acceptance remain PENDING; no model judge is treated as a human.

`evals/cases/retrieval.jsonl` adds five authored ranking cases. Four specify an expected top source (baseline 2/4, ranked 4/4); one instead requires retaining both conflicting reports. The long-page case separately verifies that an exact relevant passage replaces the irrelevant leading excerpt. These are deterministic fixture outcomes, not claims of universal ranking improvement.

Planner v2 follows the preserved first live sample (20/30 expected routes; $0.006063 across all roles). It rejects optional clarification for clear standalone questions and explicit two-subject comparisons, retains exact-original fallback, normalizes grammatical possessives, and resolves only one exact USER-topic/pricing follow-up locally. That local rule makes no paid planner call and records zero usage/SKIPPED; it does not use assistant facts as current evidence. Multiple topics remain ambiguous. One authored budget fixture was corrected to name both comparison subjects; the earlier corpus hash and full failed run remain retained rather than being rescored as a pass. A fresh complete sample is required for the changed corpus and candidate.

The second complete live sample (`485f9fe`) retained 29/30 routes, zero unnecessary clarification and 14/14 approved paired answers, but only 2/5 expected clarifications were released; it remains a failed availability sample. Five model-call receipts were unknown. Planner v3 produces fixed questions only for exact short unresolved-reference forms with no history, and continues to guard every visible question. A focused real-output probe then isolated ambiguous-context UNAVAILABLE verdicts. Adding server-owned `responseKind` to original-question metadata approved 5/5 harmless fixed clarifications and BLOCKed four unsafe controls. Output protocol v5 records that packet change; it does not authorize publication by response kind or bypass the guard. A new complete sample is required.

The third retained sample (`3c6798f`) approved 14/14 paired answers and all four clarifications that reached output safety. Its remaining unavailable route was input moderation of the context-free question “Is it better?”. Input/query prompt v6 explicitly separates neutral ambiguity from established harmful context: neutral ambiguity may reach guarded planning, while harmful prior context still requires BLOCK. The complete semantic safety corpus is rerun alongside planning to check this change. No unavailable verdict is overridden in code.
